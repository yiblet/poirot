# Exact information predicate arrays

The ten original `excel-compat-predicate-arrays.json` scenarios exposed one misplaced scalar projection: the information adapter selected a single reference member before inspecting its type, even when SUMPRODUCT supplied array demand. All ten independently authored expected results now pass unchanged. Fresh isolated Calc snapshots corroborate all ten checks; the suite's current SHA-256 and refreshed observations are recorded in `excel-compat-authored-boundaries-libreoffice.json`, along with its previous hash. Original saved-source provenance remains unchanged.

Three options were compared:

1. Reuse rectangular traversal and the existing exact scalar classifiers. Chosen: it fixes the lost shape where it occurs, follows the established array demand model, and has no new value states or function framework.
2. Automatically vectorize all scalar functions. Rejected: information predicates share an exact-type question, but numeric, reference, text and omission consumers have different contracts. These failures do not justify lifting every function.
3. Special-case SUMPRODUCT. Rejected: it would repair one observer while leaving direct arrays, dynamic spills and other array consumers inconsistent.

For ExcelDocumentation, the eight exact predicates ISERROR, ISERR, ISNA, ISNUMBER, ISTEXT, ISBLANK, ISLOGICAL and ISNONTEXT inherit the caller's expression demand. Explicit arrays retain shape, including 1x1 arrays; references expand only under existing array-demand or DynamicSpill rules. Each member is read once through the existing rectangular traversal and classified without numeric/text conversion. Both text storage variants remain text. Errors are inspected as values; operational and budget failures escape. Static spill analysis forwards the argument's dimensions and existing unbounded-name status, permitting bounded child-before-anchor discovery without extending the dynamic producer system.

The deferred host has an inherited-demand constructor alongside its existing scalar, array-prefix and selected-result constructors. It retains its existing omission metadata and memoizes evaluation once. Scalar predicates still use the same precise host scalar projection, including caller-coordinate selection in two-dimensional references and MissingArgEval distinct from BlankEval. PinnedPoi retains its previous scalar-array behavior. Both profiles record BuiltinPolicy dependence so retained results invalidate on policy changes. TYPE, N, T and ISREF are not lifted. No new argument conversion policy is needed: exact type inspection is not conversion.

## Evidence and limits

Microsoft's [IS functions documentation](https://support.microsoft.com/en-us/excel/functions/is-functions) specifies exact type inspection without converting value arguments. Numeric text remains text and logical values remain logical. The unchanged scalar predicates implement that contract; positional mapping applies the same question to each member.

`information-array-probes.json` retains two diagnostic source suites, hashes, typed Calc observations and every disagreement. The first 18-check run has 14 agreements. An explicit mixed rectangle gave ISNUMBER checksum 145 instead of 129 and ISLOGICAL 0 instead of 16; an explicit logical array likewise appeared numeric to ISNUMBER. Replacing stored logical inputs with TRUE() formulas and constructing booleans through IF did not remove the difference: the second 13-check run has 8 agreements, while scalar ISLOGICAL(TRUE()) remains true. These observations refute the initial hypothesis that the discrepancy was solely OOXML boolean import. We retain the simple documented exact-type rule rather than adding a Calc-specific logical-array conversion. No native Excel execution is claimed for these additional logical-array probes.

Calc also accepts omitted literal members (`{,1}` and `{}`), whereas Poirot's pinned parser rejects that syntax. The raw diagnostic disagreements remain visible; this change does not broaden parsing or introduce omission flags. Existing valid scalar omitted results retain their distinct missing metadata. Named arrays retain the existing unsupported static-footprint limitation at both child-first discovery and anchor publication. SUM's scalar reference-expression demand remains unchanged, while SUMPRODUCT requests array demand.

A prior IF regression observed `ISBLANK(IF({TRUE},D1,0))` directly in an ad hoc DynamicSpill call. It now uses AND as a scalar observer because the predicate correctly retains the singleton array. New direct stored-formula tests verify boolean singleton publication, an untouched neighboring physical blank, and ISREF returning false. The public ad hoc dynamic-array limitation is preserved rather than silently collapsing singleton arrays.

Tests cover mixed 2x4 types and exact positional weights, explicit row/column/rectangular arrays, errors and missing scalars, both profiles, scalar caller-coordinate selection, once-only volatile evaluation, operational and allocation refusal through IFERROR, retained snapshots and edits, policy changes in both directions, direct singleton publication, nested predicate spills and child-before-anchor bounds. Bytecode/tree parity includes predicate arrays under both builtin profiles and resource limits. Raw snapshot VERSION advances 32 to 33 and COMPATIBILITY_REVISION 33 to 34 because prior retained scalarized results are no longer valid.
